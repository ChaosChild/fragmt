## What ships

- **OKF mode is a config flag.** `.fragmt.json` gains `okf: true`, set only by `fragmt init --okf`. Absent ⇒ legacy behavior byte-identical; `loadConfig` tolerates the key like `authors`/`agents`.
- **`fragmt init --okf`** works on fresh AND existing repos (D1): plain re-init still refuses an existing config, but with `--okf` the flag flips instead. Adopt, don't rewrite: existing docs are validated, findings printed, no file rewritten by init itself. Init commits the per-directory `index.md` set and populates `references`/`referenced-by` repo-wide — single-pass adoption (init → `validate --fix` → done). Composes with `--folder --new` for a nested bundle (the #16 shape; outer redirect flow untouched).
- **Conformant defaults:** in OKF mode every NEW doc gets minimal frontmatter — `type: concept` (`DEFAULT_TYPE`; any non-empty type is conformant, consumers MUST tolerate unknown types, spec §4.1). Legacy `createDoc` behavior unchanged.
- **`fragmt validate`** (OKF repos; exit 2 + `init --okf` hint otherwise) checks the three §11 clauses: (a) every non-reserved `.md` has parseable YAML frontmatter; (b) non-empty `type`; (c) `index.md`/`log.md` follow §8/§9 when present — index carries no frontmatter except a root `okf_version`; log date headings are `## YYYY-MM-DD`, newest first. One finding per line, grouped by clause. **`--fix`** (D4): one commit that prepends missing frontmatter blocks, adds missing `type: concept`, and (re)populates `references`/`referenced-by` — inserted through the raw-splice mechanics of `prepareDocWrite`; existing YAML is never re-serialized.
- **Reserved names** (§3.1 MUST NOT hold concepts): `index.md`, `log.md`. Renames/creates targeting a reserved basename → 400 (server PATCH `{to}` + POST /api/docs). Reserved files are exempt from the `type` requirement and never carry the derived fields. Renaming a reserved file to something else stays legal (validate then flags the missing `type`). `log.md` is never auto-maintained.
- **Generated `index.md`** (D2, per directory holding concept docs): concepts grouped under `# <Type>` sections; entries `* [Title](/abs/path.md) - description` (§8 SHOULD: the linked concept's `description`; omitted when absent); subdirectories listed under a final `# Subdirectories` section. Absolute bundle-relative links per the §6.1 recommendation. Root index alone carries frontmatter `okf_version: "0.2"` (§12). Regeneration happens on membership change only — create/move/rename/delete and once after merge conclude — never on content saves; it rides the triggering `commitAs` commit. The post-conclude regen also settles mechanical `index.md` conflicts by regeneration.
- **References core (A1):** OKF-mode saves derive two frontmatter fields from body markdown links — `references` (targets that resolve to existing docs; both §6.1 forms, `/abs/path.md` and relative; broken links tolerated and skipped) and `referenced-by` (reverse edges). Propagation diffs the doc's previous `references` list (read from its own frontmatter pre-write) against the newly derived list and rewrites only the changed targets' `referenced-by` — one commit, 1 + |symmetric difference| files. Self-links excluded. Body links stay canonical; the fields are a derived cache, legal under the §4.1 extension rule. `ponytail:` full-graph recompute per derivation, not an incremental index — fine at fragmt scales, upgrade path noted in code.
- **Server/UI:** `GET /api/validate` returns the findings JSON (route before the `/api/*` 404 fallback); `/api/meta` exposes the OKF mode flag. Sidebar shows a compact OKF-only banner (D5): "N non-conformant docs" expanding to path + clause reason, fetched on load and after saves. No per-doc chips — the fix affordances are #33's editor. `index.md`/`log.md` render as ordinary docs in tree/search/meta with no special-casing.

## Pipeline

1. **Core config** — `src/core/config.ts`: `Config.okf?: boolean`; `writeConfig` emits the key only when true; `loadConfig` tolerant.
2. **Core okf** — new `src/core/okf.ts`: `RESERVED_NAMES`, `DEFAULT_TYPE`, `isReservedBase(name)`, `validateOkf(docsRoot)` → `{ conformant, findings: { path, clause: "frontmatter" | "type" | "reserved", detail }[] }` walking the same doc enumeration every other surface uses (`treeDocPaths` + the gitAllowList path set — no second walker); `generateIndexes()`; `extractRefs(doc)` → resolved targets (every resolved path containment-checked against docsRoot — link text is user input feeding file writes); `propagateRefs()` → the 1+N write set; `fixOkf()` composing the three repairs. `readDoc` (cache-bypassed gray-matter) is the parser of record for clause (a).
3. **Core wiring** — `src/core/files.ts`: `createDoc` prepends the `type: concept` block in OKF mode; create/move/delete/folder paths call index regen + ref propagation before their `commitAs`. `src/core/docs.ts`: the `writeDoc` save path calls `propagateRefs` (previous list captured before write); a stale-version target aborts the whole batch (409 semantics). `setTitle` untouched.
4. **CLI** — `src/cli/index.ts`: `--okf` in parseArgs + usage; `runInit` branch (fresh → OKF config; existing config + `--okf` → flip + report + index/refs commit); new `validate` command in dispatch + usage — findings print, `--fix`, exit 0/1/2.
5. **Server** — `src/server/index.ts`: `GET /api/validate`; OKF-mode create carries frontmatter; PATCH `{to}` reserved-basename guard → 400; conclude-merge triggers index + refs regen.
6. **UI** — `ui/src/api.ts` `fetchOkfValidate`; `ui/src/Sidebar.tsx` banner above the doc list, expandable, OKF mode only, refreshed after saves.
7. **Docs** — README OKF section citing the new canonical spec repo; BACKLOG graduation entry rides the round PR at merge.

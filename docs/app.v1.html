fragmt is one core library with thin heads. The layering is strict: the core owns every repository operation, and each head (web server, CLI, UI) is a thin adapter over ita thin adapter over it. There is no second implementation of "save a doc" anywhere – the UI's save button and the agent CLI end up in the same functions.

src/core/    git, docs, drafts, comments, okf, sync, search, graph, github
src/server/  a Hono HTTP app for the UI (+ the OAuth gate in auth.ts)
src/cli/     operator verbs (index.ts) + the agent namespace (agent.ts)
ui/src/      the React editor (Vite; served from ui/dist in production)

01The git layer

The whole git surface is one function in src/core/git.ts: execFile("git", args) with no shell, ever. It resolves trimmed stdout and rejects with a typed GitError carrying the exit code and both streams. Everything else – branches, merges, log walks, diffs – is argument lists over this seam. A per-spawn env merge is the one credential channel: secrets ride environment variables, never argv, never repo config, never disk (see Sync for the push identity this enables).

02The commitAs mutation seam

Every write in fragmt ends at one function, src/core/commit.ts:

commitAs(user, { files, message }, repoRoot) → sha

user is both the commit author and the committer – the committer rides the same identity as per-spawn env, so it is never written to git config. Doc saves, comment sidecars, metadata edits, restores, OKF repairs: all of them stage their files and commit through this seam. Pushes reuse the same identity – see Sync An identical-content save is not an error – the staged no-op is detected and the current HEAD returned instead.

/

Who user is depends on the caller:

  • Local mode (plain fragmt serve, the CLI): reads git config user.name / user.email. A missing identity is a hard error – committing with a fabricated author is worse than refusing to save.
  • Auth mode (fragmt serve --auth): the signed-in GitHub user, with the GitHub noreply address.
  • The agent CLI: --author "Name <address>", parsed git-style.

03The one exception to the seam

The merge commit itself deliberately bypasses commitAs: git merge --no-edit runs with the same per-spawn identity, because a merge has two parents and no files of its own to stage.

Guide

Sync

How fragmt keeps your copy current – pull before edit, push as you, never force.

Sync runs on an interval, on window focus, and before every edit: you never draft against a stale copy. A pull is a fetch plus a rebase of the current branch; if the rebase stops, the doc stays readable behind a calm banner that names the file and the one next step.

In auth mode every push is made as the signed-in user. The token rides an environment-injected http extraheader for that one spawn – never argv, never repo config, never disk – and is scrubbed from any error text before it reaches the UI.

The mirror pushes all branches, never with force, so drafts stop living only on one machine.

When a pull would overwrite unsaved edits, the pull waits: the banner names the doc, and saving or discarding releases it.

Conflicts never auto-resolve. A rebase that stops leaves main untouched and opens the resolution view with each conflicting passage side by side.
